# Architecture

`NotebookViewModel` owns immutable editor state. Compose renders library, page grids, dialogs, Settings, and tool surfaces. A single `NotebookCanvas` bridges Compose to `InProgressStrokesView` so Android pointer IDs, historical samples, tool types, pressure/tilt axes, hover, and cancellation remain available. Finished strokes hand off to `CanvasStrokeRenderer` in the same UI loop as the dry layer invalidation. Mesh reconstruction and image decoding happen off the input thread.

Every page has a fixed coordinate space (default 1000 × 1414) and one ordered `List<Layer>`. Text, images, and vector strokes share that list; the last element is in front. The viewport matrix alone handles fitting, zoom, pan, rotation, and window resizing. Input uses its inverse. Geometry is never saved in screen pixels. Drawing does not wait for serialization, disk writes, image decoding, or HTTP.

`DiskStore` stores a versioned JSON workspace per hash of repository + branch and content-addressed original image files. One IO actor sequences writes. A synced temp file is atomically renamed; the last complete snapshot is kept separately. A failed parse tries the previous snapshot and saves the damaged original for recovery. Unsupported formats and invalid geometry are rejected. Image blobs are written before document references. Unreferenced images are retained to preserve undo and branch recovery; garbage collection is intentionally absent in v0.1.

Each branch records its document, merge base, remote head, last page, and backup timestamp. Undo stacks are bounded and session-local; notebook content is durable. GitHub operations execute on IO and preserve edits made while upload is in progress. Push advances the merge base only to the uploaded snapshot, leaving any newer document changes pending. Pull merges against the current local state at completion. Failed remote requests leave local documents untouched. Credentials are separated from notebook storage.

The backup protocol uses GitHub's Git Database API. Blobs and a tree are committed with the observed head as sole parent, then the branch is advanced with `force=false`. This is a fast-forward race guard: if another writer advanced the head, that writer's commit is not an ancestor of the prepared commit and GitHub rejects the update. Preflight comparisons improve the error message but are not the safety mechanism.

The screen is independent of brand-specific stylus SDKs. Pen-only accepts Android stylus/eraser tool types; finger drawing is opt-in. The input policy blocks touch for the whole gesture after stylus activity and adds a short cooldown. Navigation swipes require an explicitly selected navigation tool, fit zoom, a predominantly horizontal bounded-duration gesture, and a clean touch sequence. Hardware reporting quality remains a device acceptance concern.

Known scale limits: snapshots are rewritten on edits, uploads currently resend referenced image blobs, and text does not have rich formatting. The format validates at most 20,000 pages, 100,000 objects per page, and 20 MB per imported image; practical memory/performance limits are lower and must be profiled on hardware before claiming large-notebook performance. There is no live collaboration or background network scheduler. Autosave works offline; GitHub actions are explicit.
